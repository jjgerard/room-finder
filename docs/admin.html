Refresh the datapull the current timetables from Resource Booker

Reading what the site currently holds…

1 Sign in to Resource Booker

This page cannot sign you in or read the timetable itself. The API wants a token that Microsoft issues inside the booking app, and a page on this domain has no way to get one — so the reading happens in a tab you are already signed in to, and comes back here as a file.

The address is kept in this browser so you only type it once.

2 Read the term, in that tab

Do this while looking at the booking page, signed in. Nothing to install: it runs in the tab you already have open.

  1. Switch to the Resource Booker tab. Press F12, then the Console tab.
  2. If it says pasting is disabled, type allow pasting and press Enter. Chrome and Edge ask this once per profile.
  3. Paste, press Enter. It prints Waiting for the app to send a request… — when it does, click the room search box in the page. It needs the booking app to make one request of its own before it can borrow its credentials, and a real click is the surest way to cause one.
  4. It then reads about 550 rooms four at a time and downloads snapshot-autumn.json. Two or three minutes; it prints its progress as it goes.
If it keeps saying it is waiting

It needs the booking app itself to send one request, which it then replays — it never reads your token, and it cannot invent a request of its own that would carry your credentials. Clicking the room search box, typing a letter in it, or pressing the calendar's next arrow all do it. It waits three minutes and continues the moment it sees one; a synthetic keystroke is tried first but a framework will often ignore one.

If the console will not take a paste

Use Download it instead, then drag the saved .js file onto the Sources panel, or open it and copy from there. Firefox asks you to type allow pasting too; Safari needs Develop → Show JavaScript Console turned on first.

Or run it from a terminal instead

In a clone of the repository, node tools/fetch-term.mjs --term autumn --refresh drives its own browser and writes the file for you. It needs npm install and npx playwright install chromium first — which is why the console route above is the one to reach for when those are giving trouble.

3 Check what changed

Drop the file here. Nothing is uploaded and nothing is written — this is the same comparison timetable/refresh.js --dry-run makes, run in your browser so you can see it before you touch the repo.

Drop snapshot-….json here or click to choose it

4 Write it, in the repo

A web page cannot write into a folder on your disk, so this last step is a terminal — but it is one command, and there is nothing to install: it uses only what Node ships with, so it works in a fresh clone with no npm install.

Easiest way to avoid typing the path: type the command below as far as the space, then drag the downloaded file onto the terminal window — it pastes its own path. Then press Enter.

It prints what it changed, packs the site data, and stops if the snapshot looks like a failed fetch. Add --dry-run to see the same comparison as above without writing anything. Then git commit and git push to publish.

This refreshes the timetables as they stand, not the rebuild. The clash graph — which classes share students — was inferred from the timetable as it was, and the API carries no enrolment data, so it stays as it is. The rebuilt terms are solutions to the old timetable too: if much has moved, re-solve them (node timetable/solve.js --term autumn --seeds 30 --clashes evidenced --out docs/data) rather than leaving them claiming to be a repair of something that has changed.
