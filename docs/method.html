How it was built

Short version: represent a lecture and its seminar as one object that cannot come apart, then repair room conflicts by swapping rooms before ever moving a time.

1. The problem, stated precisely

Belfast's current spring timetable puts hundreds of classes in more than one room — a class runs in room A in most weeks and room B in the rest, because something else took room A that week. Give each of those classes a single room and the conflicts become visible: 309 pairs of classes then want the same room at the same time.

That, plus closing the gaps in lecture/seminar pairs, is the whole problem. Nothing else about the timetable is wrong.

2. What counts as a hard rule

  1. No room double-booked — two classes may not share a room at overlapping times in a week they both run.
  2. No cohort or lecturer in two places — the pairs listed as unable to share a time must not overlap.
  3. Room fit — right type, enough seats. With one deliberate exemption, below.
  4. Lecture and seminar back-to-back — same day, contiguous, in the order they run today.
  5. No new same-day pairings — a cohort that does not have two given modules on one day today must not acquire that.

Two rules were added because the source data does not express them: an exam that runs straight after one of its module's classes keeps doing so, and an exam sitting in its module's usual slot keeps that slot. Only 12 of 51 exams are in their module's usual slot and only 7 follow a class directly, so each exam keeps whatever relationship it has rather than being forced into a convention the timetable does not actually follow.

3. Soft goals, in priority order

  1. Fewer classes in the 9–10am and 4–5pm edge slots.
  2. Each cohort's teaching days consecutive, without gap days.
  3. Move as little as possible — last, deliberately. Keeping the timetable still is ranked below both goals above, so the search will accept extra movement to buy a better week for students.

4. The one idea that made it work

A linked group is a single movable object, not several classes that need keeping together.

A lecture and its seminar are stored as one component with a fixed internal offset: the seminar starts exactly when the lecture ends. Placing the component places both. Back-to-back is then not a rule the search has to satisfy, notice breaking, and repair — it is a property of how the timetable is represented, and cannot be violated at all.

This is why all 146 linked groups are back-to-back here, where the earlier attempt reached 95 of 136 and concluded the rest were impossible. The earlier search treated contiguity as something to achieve and then protect; every later repair could break it again, so it settled where it could.

Couplings chain — an exam pinned to a seminar that must follow a lecture — so components are built with a union-find that carries each class's offset from the group's anchor, and contradictory couplings are rejected rather than silently resolved.

A rule that looked sensible and was not. An earlier version preserved any two same-module classes that are adjacent today. That welded whole days together: modules run parallel tutorial groups, so group 1 ending as group 2 begins is a packed day, not a relationship. Chained transitively it produced rigid eight-class trains that could not move at all. It is now restricted to exams, one partner each, no chaining.

5. The search

  1. Start from the current timetable, pulled into component geometry — which by itself closes the 73 lecture/seminar gaps and creates some new conflicts to repair.
  2. Find a class in conflict. Try every room first. Belfast's rooms are about two-thirds empty, so most conflicts resolve with a room swap, which nobody notices.
  3. If no room works, move the whole component to the best day and time available.
  4. If nothing improves it, move it to the least bad slot anyway and let the classes it displaces be repaired next round. Only accepting improvements is what leaves a search stuck a few violations short.
  5. Once nothing is broken, polish the soft goals — but only with moves that add no hard violation.

The search plateaus within seconds, so it is restarted from many random seeds and the best result kept, rather than one run being ground for longer.

6. Where the numbers are soft

The clash graph is inferred from the current timetable. A student clash means "same programme and year"; a staff clash is a proxy — same school, shared dominant room, never currently overlapping. This both over-constrains and under-constrains, and it is the single biggest reason to treat this as a feasibility study rather than a timetable to publish.

Class sizes are the seat count of the room the class is in today, not headcounts — with 17 exceptions. Room-fit decisions inherit that error in both directions.

138 of 228 rooms have no capacity recorded — nearly all studios, workshops and specialist labs. Because of this, 507 classes (24%) currently sit in a room outside their own candidate set. Enforcing room fit literally would move all of them for a data artefact, so a class staying where it is always passes, and capacity is enforced only on a class that moves. That exemption is a choice, and it can be switched off.

Exam sizes are the least trustworthy of all. Some exams currently run across 26 rooms, and the size proxy reads only the dominant one. Putting such an exam in a single room is almost certainly wrong, and those rows need real candidate numbers before anyone acts on them.

7. Reproducing it

No dependencies; Node 18 or newer.

node timetable/test.js                          # the tests
node timetable/solve.js --seeds 30 --out docs/data
node timetable/export.js                        # pack the data this site loads

timetable/lib/constraints.js and timetable/lib/suggest.js are pure and run unchanged in node and in the browser, so this site checks the rules with the same code that enforced them. docs/assets/ holds generated copies — edit the originals.

8. What would change the answer

  • Real enrolment data — replaces the inferred student clashes.
  • Real staff assignments — replaces the room-sharing proxy, which is the weakest part of the model.
  • Real headcounts and room capacities — lets room fit be enforced properly instead of exempted.
  • A policy on exams — whether a large exam may occupy several rooms, which the current one-room-per-class rule forbids.
