Ubook extensionsearch every room at once, inside Resource Booker

The rest of this site searches a snapshot — the timetable as it was when the data was last refreshed, which is what makes the rebuilt terms comparable. This extension searches live booking data instead, in the Resource Booker tab you are already signed in to. Use the site to ask what the term looks like; use this to ask what is free right now.

Clicking through the booking pages room by room does not scale: about 550 rooms across a twelve-week term is thousands of clicks, and the calendar only ever answers for one room in one week. This asks all of them in one go.

Download the extension

ubook-extension.zip · 24 KB · version 0.2.0 · Chrome 111+, Edge, Firefox 128+

What it is asked in plain words: rooms seating 45+ in BC or BD free 12:15–13:15 every Monday from 28 Sep to 7 Dec

…and what comes back is an answer, not a grid: nothing in the 34 rooms searched is free on all 11 dates; the closest miss is B_BC-01-002 (48), busy on 2 Nov only, taken by CMM125_S1/LEC/01; move the slot 30 minutes later and 4 rooms are free on every date. Each of those suggestions is a button.

1 Unzip it somewhere permanent

The browser loads the extension from the folder, not from the zip, and keeps reading it from there — so unzip it somewhere you will not tidy away. Your Documents folder is fine; Downloads is not.

2 Load it into your browser

There is no store listing, so it loads unpacked. That sounds more involved than it is: it is four clicks, and it survives restarting the browser.

Chrome or Edge

  1. Go to chrome://extensions — type it into the address bar.
  2. Turn on Developer mode, top right.
  3. Click Load unpacked.
  4. Pick the unzipped folder — the one holding manifest.json.

Firefox

  1. Go to about:debugging#/runtime/this-firefox.
  2. Click Load Temporary Add-on and pick manifest.json.

Firefox clears temporary add-ons when it closes, so it needs loading again each session. Chrome and Edge remember it.

3 Use it in Resource Booker

  1. Open Resource Booker and sign in as you always do, so you are on a …/app/booking-types/… page.
  2. Click something in the app — the room search box, or a calendar arrow. This is what makes the booking app issue its first authenticated request, which is what the extension latches on to. Without it, the first search will say so and ask you to.
  3. Click Find rooms, bottom right.
  4. Type your question and press Search, or Ctrl/Cmd+Enter.

The booking type is read from the address, so it works for any one you have access to — there is nothing to configure. Anything in your question it cannot place is listed back as “Ignored: …” rather than quietly misread, and Refine by hand has every field as a control.

What it can see, and what it cannot

It is read-only: it lists rooms and reads busy times. It never submits a booking request — that booking type is view-only anyway, and bookings go through Timetabling and Attendance.

It does not handle your login. You sign in to Resource Booker yourself, through Microsoft SSO, exactly as you always do; the extension then reuses the authorisation header the booking app attaches to its own requests, without ever reading the token's value. So:

  • no password, MFA code or token is seen, stored, or sent anywhere;
  • no API key of any kind — your question is parsed in your browser, by rules, with no AI service involved and nothing leaving the page;
  • there is no server of ours, so there is nothing to send anything to;
  • every request goes to the same API the page itself calls, with your own permissions;
  • it asks for no browser permissions at all in manifest.json — no host permissions, no storage, no network beyond the page's own.

Close the tab and it stops. If your session expires mid-search it nudges the app's own UI to refresh it and carries on — the same thing you would do by clicking a calendar arrow.

Check two rooms in the booking app before you rely on an answer — one date inside British Summer Time and one after the October clock change. Every room in the results links to its own day view. The extension converts every time through Europe/London because the API returns true UTC while labelling it +00:00, and that one habit catches the whole class of error.

The source is the same repository as this site: jjgerard/timetables — the extension is the four files at the top level, and the zip above is built from them by tools/pack-extension.sh.
